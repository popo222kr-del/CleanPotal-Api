# 메일 확인 (OFFICE › 메일 확인) 설계

웹메일 용량이 모자라 서버에서 지워야 하는 메일을 **웹메일 백업 ZIP** 으로 받아 세정통합웹에 올려 두고,
Outlook 처럼 목록·검색·본문·첨부를 확인한다. 기존 데스크톱 앱(AETS Mail Archive, Electron)의
보관·검색·열람 부분을 웹으로 옮긴 것이다.

## 원칙

| 항목 | 정한 것 |
|---|---|
| 볼 수 있는 사람 | **본인만.** 모든 조회·첨부·지우기를 로그인한 사람 번호로 거른다. 관리자도 남의 메일은 못 본다. |
| 사외 접속 | **허용.** 본인 메일만 보이므로 휴대폰 데이터에서도 연다(2026-10-12 결정). 다시 막으려면 `appsettings.local.json` 에 `"MailArchive": { "InternalOnly": true }`. 외부 접속 제한을 켜 두면 그 계정이 사외 허용 계정이어야 한다. |
| 사용 계정 | **시험 사용 — 1004 만.** `CheckSettings` 키 `site:mail-users`(아이디 JSON 배열)로 넓힌다. 없으면 `["1004"]`. |
| 메일 가져오기 | 직원이 웹메일의 백업 기능으로 ZIP 을 직접 받아 올린다. 서버는 메일 계정·비밀번호를 받지 않는다. |
| 웹메일 서버 | 건드리지 않는다(읽기·삭제 모두 없음). 서버 메일 정리는 각자 웹메일에서. |

데스크톱 앱의 "웹메일 창 자동 백업"은 옮기지 않았다. 서버가 대신 받으려면 직원 비밀번호를 서버에 맡겨야 하고,
웹메일 화면이 바뀌면 깨진다. 웹메일 공급사가 IMAP/API 를 열어 주면 그때 자동 백업을 검토한다.

## 흐름

```
웹메일 백업 ZIP ──(6MB 조각으로 나눠 올리기)──▶ 임시 파일(_upload)
                                                  │ 가져오기 시작(뒤에서 실행, 진행 표시)
                                                  ▼
                        .eml 하나씩: SHA-256 → 중복이면 건너뜀
                                     → 머리 정보(제목·보낸/받는 사람·날짜·본문 앞부분·첨부 수) DB 에
                                     → 원본 .eml 파일은 메일 보관 폴더에
                                                  ▼
                        목록·검색(DB) / 본문·첨부(열 때 원본을 다시 읽음)
```

- ZIP 안에 메일함별 폴더나 ZIP 이 한 겹 더 있어도 된다(두 겹까지).
- 받은/보낸 구분: ZIP 안 경로에 `보낸·sent·outbox` / `받은·inbox` 가 있으면 그대로, 없으면 보낸 사람이 본인 이메일(사용자 계정의 이메일)이면 보낸메일.
- 같은 메일은 사람마다 한 번만(해시 기준). 같은 ZIP 을 다시 올려도 "중복 n통 건너뜀".
- `.eml` 이 하나도 없는 ZIP 은 거절하고 기록도 남기지 않는다. 읽지 못한 메일은 실패 건수로 센다.
- 나눠 올리기: IIS 기본 요청 한도(약 28MB)를 넘지 않게 조각당 6MB. 같은 조각을 다시 보내도 한 번만 붙는다. ZIP 한 개 최대 4GB.

## 저장

| 무엇 | 어디 |
|---|---|
| 목록·검색 정보 | DB `MailImports`(올린 기록), `MailItems`(메일 한 통 한 줄). 서버가 뜰 때 표가 없으면 자동으로 만든다. |
| 원본 메일 | `Storage:MailArchivePath`, 없으면 `App_Data\mail-archive`(배포 때 보존). `{사용자번호}\{해시 앞2}\{해시}.eml` |

- 첨부 보관소(NAS 공유 폴더)와 섞지 않는다 — 개인 메일이라 공유 폴더에서 열람되지 않게.
- **DB 백업만으로는 원본이 백업되지 않는다.** 메일 보관 폴더도 백업 대상에 넣을 것(또는 `Storage:MailArchivePath` 를 백업되는 디스크로).

## 보안

- 본문 HTML 은 서버에서 정리(HtmlSanitizer: 스크립트·폼·이벤트 속성 제거)하고, 화면에서는 격리된 칸(iframe sandbox, 스크립트 불가)에 넣는다.
- 바깥 그림(http)은 태그째 빼고 "바깥 그림은 표시하지 않았습니다" 안내 — 열람 추적 방지. 격리 칸의 CSP(`img-src data:`)가 한 번 더 막는다.
- 본문 속 첨부 그림(cid:)은 2MB 이하만 바로 보이게 바꾼다.
- 첨부·원본(.eml)은 본인이 누를 때만 받는다.

## API (`api/mail`, 로그인 + MailGuardFilter)

| 동작 | 설명 |
|---|---|
| `GET access` | 메뉴 표시용 — 허용 계정인지, 지금 사내인지(이것만 확인 필터를 거치지 않는다) |
| `GET ?folder=&q=&page=` | 목록·검색(띄어 쓴 낱말 모두 포함) |
| `GET {id}` | 본문(정리한 HTML 또는 글)·첨부 목록 |
| `GET {id}/attachments/{n}` · `GET {id}/eml` | 첨부 · 원본 받기 |
| `POST upload?id=&offset=` | ZIP 조각 올리기(본문이 파일 조각 그대로) |
| `POST import` · `GET import/{jobId}` | 가져오기 시작 · 진행 |
| `GET imports` · `DELETE imports/{id}` | 가져오기 기록 · 그때 들어온 메일 지우기 |

## 화면 (웹메일과 같은 배치)

- 왼쪽: [백업 ZIP 올리기] · 메일함(전체·받은·보낸·★중요) · 가져오기 기록
- 검색: 항목(전체·제목·본문·보낸사람·받는사람·참조) + 낱말. 본문은 앞 2만 자까지 검색(`MailItems.Body`, 이 칸이 생기기 전 메일은 서버가 뜰 때 원본에서 채움)
- 필터: 기간(오늘·1주·1/3/6개월·1년·직접 입력) · 첨부 있음 · 크기(1/5/10MB 이상) — 걸린 조건은 칩으로 보이고 ✕로 끈다
- 정렬: 목록 머리(보낸사람·제목·날짜·크기) 누르기, 50/100/200개씩
- 보기: 좌우 나눔 · 위아래 나눔 · 목록만(누르면 새 창) — 고른 보기는 PC에 기억
- 새 창: 읽기 칸의 [새 창] 또는 목록에서 두 번 누르기(`/mail/view/{id}`, 사이드바 없음)
- 읽기 칸: ★중요 · 새 창 · 원본(.eml) · "이 사람 메일 모두"(보낸사람 검색) · 첨부 받기
- 좁은 화면에서는 목록 → 읽기로 바뀐다.
[백업 ZIP 올리기]는 여러 개를 골라도 하나씩 차례로 올리고, 올리기 % → 메일 정리 n통 → 결과를 보여 준다.

## 사용 계정 넓히기 (나중에)

지금은 화면이 없다. 넓힐 때 관리자 화면에 칸을 만들거나, DB `CheckSettings` 에
`Key = 'site:mail-users'`, `Value = '["1004","아이디2"]'` 를 넣는다.

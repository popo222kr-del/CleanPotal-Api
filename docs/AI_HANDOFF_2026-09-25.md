## 1. 아침에 할 일 (순서대로)

### 1-1. 개발 PC에서 받기·빌드·테스트

PowerShell 에서 실행한다(cmd 아님).

```powershell
Set-Location 'C:\Users\owner\cleanpotal-api'
git status --short --branch          # 미커밋 변경이 있으면 먼저 확인한다
git pull origin claude/review-and-work-7yqzee
git log -3 --oneline

Set-Location .\client
npm ci
npm run build                         # 화면을 src\CleanPotal.Api\wwwroot 로 만든다
Set-Location ..

dotnet test .\CleanPotal.sln          # 윈도우에서는 전부 통과해야 한다(아래 참고)
dotnet publish .\src\CleanPotal.Api\CleanPotal.Api.csproj -c Release -o .\publish
Get-FileHash '.\publish\CleanPotal.Api.dll' -Algorithm SHA256
```

- 작업 환경(리눅스)에서는 테스트 460개 중 450개가 통과했다. 실패한 10개(`MesEndpointAuthTests`, `AdminEndpointAuthTests`)는
  리눅스 .NET 에 IIS용 HttpSys 구성요소가 없어 포털을 띄우지 못해서 나는 것으로, 코드 문제가 아니다.
  9/24 에 윈도우에서 돌렸을 때는 이 10개도 통과했다. **윈도우에서 하나라도 실패하면 배포하지 말고 결과를 알려 달라.**

### 1-2. 운영 서버 배포

평소 절차 그대로다: 앱 풀 `Cleanjueon` 중지 → 보존 파일을 뺀 나머지 삭제 → `publish` 내용 붙여넣기 → 앱 풀 시작.

보존: `appsettings.local.json`, `App_Data`, `cleanpotal.db` (서버에 있는 `appsettings.local.json.before-mqtt`,
`cleanpotal.generated-20260921.db.db` 도 지우지 않는다).

**배포 전 꼭 확인할 것 — `appsettings.local.json` 에 `Database:Provider` 가 있어야 한다.**
이제 개발환경이 아니면 이 값이 없을 때 서버가 아예 뜨지 않는다(예전에는 조용히 SQLite 로 떠서 운영 DB와 갈라졌다).
값만 확인하고 연결 문자열 전체를 화면에 띄우지 않는다.

```powershell
Select-String -Path 'C:\Webjueon\publish\appsettings.local.json' -Pattern '"Provider"'
```

### 1-3. 배포 후 확인

1. 로그인, 대시보드, 근무표, 통합 일정 달력이 열린다.
2. 온·습도 화면의 가운데 표시(MQTT·Zigbee2MQTT)가 초록이다.
3. `C:\Webjueon\publish\App_Data\logs\portal-YYYYMMDD.log` 가 생겼고, 맨 앞에 `[db]`·`[schema]` 줄이 있다.
   처음 뜰 때 `HolidayOverrides` 표와 `Attachments.Scope` 컬럼, 새 인덱스를 만든다는 줄이 보이는 것이 정상이다.
4. 관리자 영역 → **공휴일 관리** 화면이 열린다.

문제가 생기면 위 로그 파일의 마지막 줄부터 본다. 되돌리려면 직전 publish 폴더로 다시 배포한다
(스키마는 **추가만** 했으므로 옛 버전이 새 표·컬럼 때문에 깨지지 않는다).

## 3. 사용자가 느낄 동작 변화

- **공휴일 관리(관리자)**: 관리자 영역에 새 메뉴. 2028년은 기본 목록이 비어 있어 경고가 뜬다 —
  2027년 6월 무렵 월력요항이 나오면 여기서 넣는다. 임시공휴일도 여기서 넣으면 근무표·달력·근태에 바로 반영된다.
- **숨긴 메뉴**: 관리자가 사용자별로 끈 메뉴는 주소를 직접 쳐도 열리지 않고, 그 메뉴만 쓰는 서버 기능도 403 이 된다.
  여러 화면이 같이 쓰는 자료(업체·인수인계·회의록)는 영역 등급으로만 정해진다.
- **동시 편집**: 회의록·배차·재고·스케줄보드·분장표 교육·주간보고에서 다른 사람이 먼저 저장했으면 안내가 뜬다(말없이 덮어쓰지 않음).
  어느 쪽을 남길지 묻는 창은 모두 **[확인] = 내 것으로 덮어쓰기, [취소]/Esc = 상대 것 불러오기** 로 뜻을 맞췄다.
- **교육 → 근무표**: 교육은 비어 있는 날만 채운다. 연차·야간이 있던 날은 건드리지 않는다.
- **교대 예측**: 2027년 이후 예측이 1주 어긋나던 것을 고쳤다. 2026년 예측은 그대로다.
- **MES**: 조회 등급(1)은 옛 MES 화면에서도 작업 버튼이 막힌다. 포털 로그아웃·퇴사·권한 회수가 5분 안에 MES 에도 반영된다.
- **첨부**: SVG 는 화면에 바로 열지 않고 내려받기만 된다. 첨부는 그 화면 영역 권한이 있어야 받을 수 있다.
- **온·습도**: MQTT 가 끊기면 Zigbee2MQTT 표시가 초록 대신 회색(모름)이 된다.
- **사용자 등록**: 다른 계정(퇴사자 포함)과 같은 이름은 저장되지 않는다 — `김철수(B)` 처럼 구분하거나, 같은 사람이면 옛 계정을 복직 처리한다.
- **DB 설정 누락**: `Database:Provider` 가 없으면 서버가 뜨지 않는다(위 1-2).

## 4. 손대지 않은 것과 이유

| 항목 | 이유 |
|---|---|
| 이름 대신 사용자 ID 로 근무표·교육 연결 | 운영 데이터 이관과 동명이인 수동 확인이 필요해 별도 승인 대상(`docs/known-issues.md` §1). 임시로 이름 중복 등록만 막았다 |
| 인수인계 분류가 업체명 글자에 의존 | 문서화된 업무 규칙이라 유지 |
| CORS 전체 허용 | 토큰을 헤더로만 보내 쿠키 탈취 위험이 없고, 다른 사내 사이트가 부를 수 있어 유지 |
| 교육 화면(OFFICE 편집)이 근무표에 반영 | 빈 날만 채우도록 바뀌어 위험이 줄었고, 교육 담당자에게 근무표 편집 권한을 따로 주지 않아도 되게 유지 |
| 쓰이지 않는 `/api/productionmeeting` | 화면에서 부르지 않지만 외부 사용 여부를 확인하지 못해 남김 |
| 재고 충돌 판정 10ms 허용 | SQL Server `datetime` 정밀도(약 3ms) 때문에 둔 여유라 유지 |
| 기동 때 SQL Server 컬럼 존재 확인을 컬럼마다 한 번씩(수백 번) | 기동 시간이 조금 늘 뿐 동작은 맞음. 느리면 한 번에 읽도록 바꾼다 |
| MES 별도 프로세스(`/mes-runtime`) | 운영에서 돌지 않는다(5206 포트 없음). 쓰게 되면 MES 쪽 `appsettings.local.json` 에도 `Database:Provider`·연결 문자열이 필요하다 |
